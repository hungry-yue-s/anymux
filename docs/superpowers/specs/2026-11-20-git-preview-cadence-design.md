# Git 交付入口与来源名称

代码任务完成并通过必要验证后，每个实际仓库或 worktree 只后台登记一次交付提交；用户点击通知中的查看后，再加载详情。

- `git show --background` 经 API 传递 `activate: false`，只更新已有的合并通知，不创建 Git block、不读取历史或 diff、不替换正在阅读的提交，也不展开侧栏。
- 普通 `git show` 和显式查看沿用即时打开行为。通知继续按服务器、tmux 实例、窗口和仓库路径合并，同提交重放不重复提醒。
- 项目规则、agent-docs 模板和已安装规则统一排除中间提交、重试、日志同步及纯文档任务；一次用户请求为任务边界，不增加定时器。
- 来源栏显示 tmux 左上角同款 `[标签] 序号:应用名`。序号取真实 `pane_index`，不能从内部 `%ID` 或数组位置推算；没有数据时用“来源窗格”，不显示内部 ID。链接窗口不猜测唯一会话，跨服务器名称取来源服务器。

首轮不增加任务累计 diff。复用通知作为最新入口，保持现有文件预览、窗口路由和当前窗口免左侧提示的契约。

验收：后台请求保持当前提交、标签、草稿、焦点、收起状态；无 Git 标签时不新建；重复和跨窗口请求可合并回看，查看时打开固定 hash；来源名称匹配实际 tmux 标题。
